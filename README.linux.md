# Linux: нюансы, диагностика и сборка

Основное описание проекта, установка пакетов (deb, rpm, AppImage, AUR) и отличия платформ —
в [README.md](README.md). Здесь собрано то, что нужно при разборе проблем на Linux: где что лежит,
что писать в лог, как собрать локально.

## Что где лежит

| Путь | Что |
|---|---|
| `~/.config/yamusic-rs/config.json` | настройки, каталог скачивания, режим, тема |
| `~/.config/yamusic-rs/log.txt` | лог (при переполнении начинается заново) |
| `~/.config/yamusic-rs/device` | id устройства для входа по коду |
| `~/.cache/yamusic-rs/assets/` | кэш шрифтов и иконок веб-версии |
| `~/Музыка/Яндекс Музыка` | скачанные треки (или папка из настроек) |
| `~/.config/autostart/yamusic-rs.desktop` | автозапуск, если включён |
| `$XDG_RUNTIME_DIR/yamusic-rs.sock` | сокет единственного экземпляра |

Токен хранится в связке ключей (GNOME Keyring, KWallet — через Secret Service), не в файле.

## Поведение, специфичное для Linux

- **Трея нет.** Закрытие окна завершает приложение; повторный запуск показывает уже открытое окно,
  второй процесс выходит. Автозапуск стартует с окном.
- **Обновление** — установка нового пакета. Кнопка «Обновить» в уведомлении открывает страницу релиза.
- **Медиаклавиши** работают через MPRIS: GNOME (`gsd-media-keys`) и KDE сами шлют команды активному
  плееру. Учтите, что часть клавиатур шлёт `Pause`/`Play` раздельно, а не `PlayPause` — оба
  варианта поддержаны; какие клавиши за что отвечают, видно в «Настройки → Клавиатура».
- **Диалоги выбора файла и папки** — через `zenity` или `kdialog` (пакет `Recommends`).
- **Мини-плеер:** размер и «поверх всех» работают, а положение окна под Wayland выбирает композитор.
- **Рендер** — Skia (software): не зависит от драйвера видеокарты, поэтому одинаково ведёт себя
  на Mesa, NVIDIA и в виртуалках.
- **Discord Rich Presence** работает через unix-сокет, включая Flatpak/Snap-версии Discord.

## Диагностика ввода

Флаг `YAMUSIC_INPUT_DEBUG=1` включает подробный журнал событий ввода:

```bash
YAMUSIC_INPUT_DEBUG=1 yamusic-rs
```

Что появится в `log.txt`:

```
ввод: размер окна 1920×1200 (k 1.5)
ввод: масштаб окна 1.5
ввод: фокус true
ввод: курсор 1500,900 физ. = 1000,600 лог. (k 1.5)
ввод: Pressed Left физ. (1500.0, 900.0) лог. 1000,600 (k 1.5)
ввод: Released Left физ. (1500.0, 900.0) лог. 1000,600 (k 1.5)
ввод: нажатие — PillButton — нажато: Скопировать код
ввод: нажатие — PillButton — клик: Скопировать код
рендер: кадров всего 320
```

Как читать:

| В логе | Что означает |
|---|---|
| `Pressed` есть, `нажатие — …` нет | событие дошло до окна, но мимо элемента (или на нём лежит прозрачный слой) |
| `нажато` есть, `клик` нет | отпускание пришлось на другой элемент: раскладка сдвинулась между нажатием и отпусканием |
| нет ни `Pressed`, ни строк `курсор` | события не доходят до окна: вопрос к композитору и фокусу |
| `наведение: … да/нет` не появляются | наведение не доходит до элементов — смотрите строки `курсор` и `фокус` |
| `рендер: кадров всего N` не растёт | окно не перерисовывается (N — счётчик кадров, пишется раз в 5 секунд) |
| `фон — нажато` | клик дошёл до окна, но не попал ни в один элемент |

## Известные исправленные проблемы

- **«Кнопки перестают нажиматься после перетаскивания окна».** Композитор забирает указатель на время
  перемещения, отпускание кнопки до приложения не доходит, и Slint остаётся с «зажатой» кнопкой:
  наведение не обновляется, клики уходят «захваченному» элементу. Теперь приложение само доставляет
  отпускание сразу после старта перемещения (`gui::settle_pointer_after_move`).
- **Код входа в верхнем регистре** — сервис принимает только нижний; выводятся как есть.
- **Истёкший код входа** — приложение само запрашивает новый (до 6 раз подряд), кнопка остаётся
  для случая ошибки сети.
- **Медиаклавиша «плей/пауза» не реагировала**, хотя кнопки в уведомлении работали: GNOME шлёт
  `Pause`/`Play`, а не `PlayPause`; обработчики `Pause` и `Stop` теперь подключены.

## Сборка в контейнере

На хосте Rust не нужен: версия тулчейна и системные библиотеки зафиксированы в образе.

```bash
podman build -t localhost/yamusic-build -f tools/Containerfile.build .

podman run --rm -v "$PWD":/src:Z \
  -v yamusic-cargo:/usr/local/cargo/registry \
  -v yamusic-target:/src/target \
  -w /src localhost/yamusic-build cargo clippy --all-targets -- -D warnings

podman run --rm -v "$PWD":/src:Z \
  -v yamusic-cargo:/usr/local/cargo/registry \
  -v yamusic-target:/src/target \
  -w /src localhost/yamusic-build cargo test

podman run --rm -v "$PWD":/src:Z \
  -v yamusic-cargo:/usr/local/cargo/registry \
  -v yamusic-target:/src/target \
  -w /src localhost/yamusic-build cargo deb
# → target/debian/yamusic-rs_<версия>_amd64.deb
```

Пакеты rpm и AppImage собираются в CI (`.github/workflows/build.yml`): `cargo generate-rpm` и
`tools/appimage.sh`. Там же гоняются `cargo clippy`, `cargo test` и `cargo audit`.

Проверка установки на чистой системе:

```bash
podman run --rm -v "$PWD":/src:Z ubuntu:24.04 sh -c '
  apt-get update -qq &&
  apt-get install -y --no-install-recommends /src/target/debian/yamusic-rs_*_amd64.deb &&
  dpkg -s yamusic-rs | grep -E "Version|Depends"'
```
